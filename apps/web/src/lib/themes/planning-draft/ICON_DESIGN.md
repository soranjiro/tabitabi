# 予定の種類と絵文字：わかりやすさの設計

この文書は「予定表」（`planning-draft` / 互換 `planning-map`）で使う種類の表示を、ユーザーが**選ぶ前に意味を予測できる**ようにするための判断記録。永続化する `StepType` の値は変更せず、表示の責務を `standard/core/utils/step-type.ts` に集約する。

## なぜ以前の表示はわかりにくかったか

1. **絵文字の意味が用途とずれていた。** 🎌は観光一般ではなく祝い事・国旗を連想させる。🚄は普通列車まで含む「電車」に対して新幹線に見える。🚗を「一般的な移動」に、🚙を「車」に使うと、一目で区別できない。
2. **種類と画面で絵文字が異なっていた。** 共通の種類定義には「食事 🍽️／宿泊 🏨／観光 🎌／電車 🚄」があるのに、予定表の一覧は別の関数で「食事 🍽／宿泊 🛏／観光 📍／電車 🚆」を表示していた。編集時の選択肢はさらにSVGで、同じ種類を選んだか確かめにくい。
3. **表示漏れがあった。** 予定表の独自判定では「船」「一般的な移動」「一般的な予定」の区別が不十分で、設定した種類が📝に丸められる場合があった。
4. **短い名称だけでは意味がわからず、長い名称は読みにくかった。** 「一般的な予定」はカテゴリ名として長いうえ、何に使うか説明しない。「一般的な移動」も手段未定と車移動を混同しやすい。しかも予定の詳細画面に `normal:general` のような内部IDが出ていた。
5. **候補が見つからなかった。** 選択肢は横スクロール方式で、一部の種類が隠れる。特にスマートフォンでは「船」などが存在すること自体に気づきにくく、ボタンも密集していた。
6. **抽象的な選択操作だった。** 「予定のアイコン」と案内しながら、実際はアイコンの着せ替えではなく予定の種類（保存データ）を変えていた。種類のグループ分けも利用者の語彙と一致しにくい。
7. **小さい絵文字に依存しすぎた。** 🍽️のような細い字形や環境によって見え方が変わる絵文字は、小さなサイズで識別しづらい。名前が同時に読めることが必要。

## UIでの解決方法

- **種類を選ぶ時**：予定表だけを「全候補が見えるグリッド」にする。小画面は2列、それ以外は3列。グループ名を「予定」「移動」とし、絵文字と短いラベルを並べ、選択状態・キーボードのフォーカスを明示する。選んでいる種類の説明を直下に表示し、切り替えるたびに更新する。選択肢には説明文（title属性）も付ける。
- **予定一覧・詳細・地図**：すべて `getStepTypeIcon` / `getStepTypeLabel` を使う。地図は同じ絵文字と既存の予定タイトルラベルを利用し、位置が密集するときのラベル重なり回避を保つ。
- **種類が未指定・過去の未知値**：必ず「📌 その他」にフォールバックする。内部IDを利用者に露出しない。
- **標準テーマ**：従来のSVGスタイルは維持するが、短い名称と説明は共通化する。予定表でのみ絵文字の見た目を統一する。
- **文言**：「予定のアイコン」ではなく「予定の種類」。見た目だけの変更だと誤解されないようにする。

## 読みやすさの限界と追加確認

絵文字の字形はOS・ブラウザーにより異なる。「🏯 観光」には城以外の景色も含むため、絵文字だけで分類を判断させない。選択画面では必ずラベルを併記し、一覧はタイトルを、地図は可能な限りタイトルラベルを併記する。密集してラベルを隠す既存処理が働く場合は、ピンをタップして詳細を確認できる。

確認すべき項目：スマートフォン幅（320/375/430px）で全種類をスクロールなしで**グループ内**表示できること、ブラウザーの200%拡大で文字が欠けないこと、選択・保存・編集後に種類が維持されること、過去の未指定・食事別名・船移動でも適切な絵文字と名称が出ること、キーボードで全候補を選べること、地図でピンとラベルが操作できること。自動テストでは種類の重複・未指定値・過去の別名を確認する。
