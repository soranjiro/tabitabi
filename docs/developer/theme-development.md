# テーマ開発

テーマは、共通のしおりデータを異なる見せ方で表示するためのUI単位です。

## 正本

選択できるテーマ、表示名、有効状態、既定値は`apps/web/src/lib/themes/catalog.ts`を正本とします。

ドキュメントにはテーマの全一覧を固定しません。ソースに存在していてもカタログで無効なテーマは、利用者が選べる機能として扱わないでください。

## 実装の考え方

- しおり・予定などの共通データ構造はテーマへ閉じ込めない
- 複数テーマで使う機能は`apps/web/src/lib/`配下へ共通化する
- テーマ固有の表示・装飾は各テーマ配下へ置く
- API URLや認証処理をテーマ内へ重複実装しない
- 公開・閲覧・編集など権限の違いをUIで正しく反映する

具体的なディレクトリ構造は`apps/web/src/lib/themes/`と既存テーマを正本とします。

## 新しいテーマを追加する

1. テーマ実装を追加する
2. `catalog.ts`へ選択肢とメタ情報を追加する
3. テーマローダーへ登録する
4. 必要であればデモやプレビューを追加する
5. 対応するunit testとE2Eを追加する
6. ユーザー向け説明が必要な場合だけ`docs/user/`を更新する

カタログとローダーの両方に登録されていることを確認してください。

## 共通機能

持ち物、お金、印刷、共有など、テーマに依存しない機能は可能な限り共通機能として実装します。

特定テーマにだけ操作入口を置く場合でも、データ層やAPIまでテーマ固有にしないようにしてください。

## テスト

最低限、次を確認します。

- テーマを選択して表示できる
- 予定の追加・編集・削除が権限に応じて動く
- 閲覧専用では編集UIが出ない
- テーマ切り替え後に前のCSSや状態が残らない
- モバイル幅で主要操作が隠れない
- デモが実データへ書き込まない

地図など外部サービスを使うテーマでは、トークン未設定、権限拒否、通信失敗も確認します。

## PWAとパフォーマンス

テーマはPWAの初期表示と更新体験へ影響します。

- 大きな地図やoverlayは必要になるまで遅延ロードする
- 画像は表示用途に合わせて最適化する
- グローバルCSSで別テーマを汚染しない
- standalone表示とsafe areaを確認する
- Service Workerのキャッシュに古いassetが残っても致命的に壊れないようにする
- 新しい依存を追加する前に、既存依存やブラウザ標準APIで代替できないか確認する

## Step Type

予定種別の正本は`packages/types/`内の定義と、Web側の表示helperです。新しい種別を追加する場合は、共有型、選択UI、表示、印刷、テストなど影響する箇所をまとめて更新してください。

具体的な種別一覧はソースコードを正本とし、このページへ固定しません。
