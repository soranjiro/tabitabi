# ドキュメントデザインガイドライン

このドキュメントは、`/docs` の見た目と情報設計を継続して改善するための基準です。ユーザー向けガイドと開発者向けガイドの両方に適用します。

## 目的

ドキュメントは「情報量が多くても迷わず読めること」を最優先にします。そのうえで、たびたび本体の「旅のしおり・紙・風景」を感じる穏やかなデザインへ寄せます。

- 本文を長時間読んでも疲れにくい
- 現在位置、次に読むページ、検索先が分かりやすい
- PC とスマートフォンで同じ情報へ無理なく到達できる
- 表、コード、引用、Mermaid など内容の種類を見分けやすい
- キーボード操作、フォーカス表示、コントラスト、動きの低減に配慮する
- ドキュメント固有のデザインを一か所で管理する

## PR #267 時点で見つかった問題

### 1. スタイルの二重管理

生成器 `apps/web/scripts/build-docs.ts` が既にドキュメント全体の CSS を持っている一方、別ファイルの `docs-refresh.css` を配信時に強制挿入していました。

この構成では、どちらが正しい値なのか分かりにくく、修正のたびに上書き順を意識する必要があります。ドキュメントの共通デザインは生成器側へ集約します。

### 2. `!important` に依存した上書き

色、余白、文字サイズ、罫線など広い範囲で `!important` を使うと、ページ固有の表現や将来のコンポーネント追加が難しくなります。

共通スタイルは詳細度を低く保ち、コンポーネント名とデザイントークンで制御します。

### 3. ブランドとの距離

従来のドキュメントは一般的な青系 SaaS ドキュメントの見た目に寄っており、ホーム画面の特徴である以下の要素とつながりが弱い状態でした。

- 濃いネイビーの文字
- 白い紙を思わせる背景
- 風景になじむ青・グレー系アクセント
- 明朝体を使った大きな見出し
- 控えめな罫線、丸み、旅のルートを連想させる装飾

ドキュメントでは装飾を増やしすぎず、タイポグラフィと色、紙面感だけを共通化します。

### 4. 本文幅と余白のバランス

固定幅のサイドバーと `main` の最大幅・パディングが別々に設定されており、画面幅によって本文が左に寄って見えたり、利用できる横幅が不自然に狭くなったりします。

本文は読みやすい行長を基準に中央へ配置し、外側余白は `clamp()` で滑らかに変化させます。

### 5. 日本語本文に対して見出しが大きすぎる

3rem 近い H1 や強い字間調整は英語のランディングページには有効ですが、日本語の長い見出しでは改行が増え、本文との密度差が大きくなります。

H1 は約 2.4rem を上限にし、明朝体をアクセントとして使います。本文はゴシック体を維持します。

### 6. 行間が一律

`p, li` を同じ大きな行間にすると、箇条書きが間延びします。

本文は 1.8 前後、リストは 1.7 前後を目安にし、項目間の余白でまとまりを表現します。

### 7. 表の横スクロール方法

`table` 自体を `display: block` にすると、本来のテーブルレイアウトを崩しやすくなります。

生成時に `.table-scroll` で表を包み、ラッパーだけを横スクロールさせます。表要素そのものはテーブルとして保ちます。

### 8. コード表現の一貫性

インラインコードだけ強いピンク、コードブロックは濃いグレーという組み合わせは、たびたび本体の色設計から外れていました。

インラインコードは淡い青灰色の背景とネイビー系文字、コードブロックは濃紺に統一します。

### 9. 引用・注意書きの主張が強い

引用全体が濃い青で塗られると、長いページでは注意書きが本文より目立ちます。

左罫線と淡い面だけにし、本文の流れを止めない強さにします。

### 10. モバイルでナビゲーションが長すぎる

従来はスマートフォンでサイドバー全体が通常フローへ入り、ナビゲーションが最大 50vh 表示されます。ページを開いた直後に本文へ到達しづらい状態です。

モバイルでは「目次」ボタンでナビゲーションを開閉し、初期状態では本文を優先します。

### 11. フォーカス表示が弱い

リンク、検索、ナビゲーションボタン、ページ送りで明確な `:focus-visible` がありません。

キーボード利用時だけ分かるフォーカスリングを共通で表示します。

### 12. ナビゲーションの開閉状態が支援技術へ伝わらない

階層ナビの開閉ボタンは見た目だけが変化し、`aria-expanded` が更新されていませんでした。

開閉時に `aria-expanded` を同期します。

### 13. 検索 UI の意味付けが弱い

検索欄には見た目上のプレースホルダーしかなく、検索結果領域も状態変化が伝わりにくい構造でした。

検索領域に `role="search"`、入力にラベル、結果領域に `aria-live` を付けます。

### 14. スクロールトップボタンの説明不足

アイコンだけの固定ボタンにはアクセシブルネームが必要です。

`aria-label="ページ上部へ戻る"` を付けます。

### 15. モーション低減への配慮不足

ホバー移動やスムーズスクロールを常に有効にすると、動きを減らしたいユーザーにも適用されます。

`prefers-reduced-motion: reduce` ではアニメーションとトランジションを停止します。

### 16. 検索結果のタイトルがファイル名由来

検索結果では Markdown の H1 ではなく `basic-usage` のようなファイル名からタイトルを生成していました。

検索インデックスもページ H1 を利用し、ナビゲーションと検索結果の名称を一致させます。

### 17. デスクトップとモバイルの境界が急

固定値だけで切り替えると、タブレット幅でサイドバーと本文が窮屈になります。

余白と文字サイズには `clamp()` を使い、レイアウト変更が必要な箇所だけメディアクエリを利用します。

### 18. ページ送りが本文と切り離されて見える

前後リンクは単なる枠付きリンクだったため、ページの終端であることが弱く、タイトルが長い場合の情報量も少なくなります。

紙のカードを思わせる面と十分なクリック領域を持たせ、前後方向とページ名を明確に分けます。

## デザイン原則

### 読むための静かな紙面

背景は真っ白一色ではなく、外側をわずかに暖かいグレー、本文を白に近い紙色にします。強い影やグラデーションは使いません。

### たびたびらしさは見出しと色で出す

本文まで装飾的にせず、H1/H2 の明朝体、ネイビー、淡いブルーグレー、細い点線などにブランド表現を限定します。

### 情報階層を色だけに依存しない

見出しサイズ、余白、罫線、背景、太さを組み合わせます。アクティブなナビ項目には色に加えて左側のラインを表示します。

## タイポグラフィ

- 本文: `-apple-system`, BlinkMacSystemFont, `Hiragino Kaku Gothic ProN`, `Yu Gothic`, sans-serif
- 大見出し: Georgia, `Yu Mincho`, `Hiragino Mincho ProN`, serif
- H1: `clamp(2rem, 4vw, 2.55rem)`
- H2: `clamp(1.35rem, 2.5vw, 1.6rem)`
- 本文: 16px を基準、行間 1.8
- 最大本文幅: 約 820〜900px の範囲

## コンポーネント

### サイドバー

- デスクトップでは左に固定
- 本文との境界は細い罫線のみ
- アクティブ項目は淡い背景 + 左ライン
- 検索結果はサイドバー内で重なるポップオーバー
- モバイルでは目次ボタンから開閉

### 見出し

H1 はページの主題を一度だけ示します。H2 は長いページの章区切りとして十分な上余白を取ります。H3 以下は本文用ゴシック体を使います。

### 表

- 外側にスクロールラッパー
- ヘッダーは淡い面
- セルの上下余白を確保
- モバイルでも列を潰さない

### コード

- インラインコードは本文と同じ行に自然に収まる小さな面
- コードブロックは濃紺背景
- 横スクロールを許可
- 長い行を無理に折り返さない

### 引用・注意書き

- 左罫線 3px
- 背景は `Accent soft`
- 角丸は小さめ
- 本文より強くしすぎない

### 前後ナビゲーション

- 2カラムを基本とし、狭い画面では縦積み
- ラベルとタイトルを別行にする
- リンク全体をクリック可能にする

## レスポンシブ基準

### 769px 以上

サイドバー + 本文の2カラム。本文は中央寄せで最大幅を制限します。

### 768px 以下

サイドバーは上部のコンパクトなヘッダーへ変え、目次と検索を必要なときだけ開きます。本文は左右 20px 前後を確保します。

## アクセシビリティチェック

- 文字と背景のコントラストを十分に取る
- すべての操作要素をキーボードで到達可能にする
- `:focus-visible` を消さない
- アイコンだけのボタンに `aria-label` を付ける
- 開閉ボタンの `aria-expanded` を同期する
- 検索結果の変化を `aria-live` で通知する
- `prefers-reduced-motion` を尊重する
- 表を視覚上の都合で非テーブル要素へ変更しない

## 実装ルール

1. 共通スタイルは `build-docs.ts` のテンプレートへ集約する。
2. 配信時の HTML 文字列置換で CSS を後付けしない。
3. 共通値は CSS カスタムプロパティへまとめる。
4. `!important` は原則使用しない。
5. ページ固有の装飾が必要な場合は、意味のあるクラスを Markdown/renderer 側で付与する。
6. 新しい UI を追加したら PC / 768px / 390px 前後を確認する。
7. 検索、ナビ開閉、前後リンク、表、コード、Mermaid を最低限の回帰確認対象にする。
